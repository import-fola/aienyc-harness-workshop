Rules that keep it layered

  • Tests: tests/layerK runs with only layers ≤ K on.

The split that makes it trustworthy

Models propose. Code with no model decides what counts.

Model roles (prompt files in each package)

  • Interviewer: asks, proposes the plan
  • Spec, example and code writers: build each step
  • Checker: a blind second pass on the examples
  • Analyst: picks modules, writes the reply
  • Side assistant: talks in branches, proposes changes
  • Reviewer: raises challenges

Fixed code: no model involved

  • Brief validation (brief.py)
  • Safety read of model-written code (safety.py)
  • The gate and runner (gate.py, runner.py)
  • Fingerprints, stale, registry (registry.py)
  • The number check (provenance.py)
  • Figures, chips, the re-run engine (answers/)
  • Proposal and challenge filters

Only harness/model/ imports a provider SDK. Every test runs offline against a scripted model, so the fixed code is what gets tested.

Principle 1 · Shared Domain · layer 1

Agree the plan before any number.

What is obvious to you is not what the model learned. Start from the goal and work backwards, together.

Without it

  • The model guesses the problem, then solves the guess.
  • No way to tell your words from its inventions.
  • Corrections arrive after the numbers.

With it

  • A plan diagram: goal, steps, inputs.
  • Every item tagged with where it came from.
  • Nothing is built until you click Accept plan.

Principle 2 · Consistency · layer 2

Numbers come only from tested code.

Write the calculation once. Run it the same way every time. The model picks the tool; it never does the arithmetic.

Without it

  • Arithmetic in the model's head.
  • New code for every question.
  • Same question, different answer.

With it

  • Each calculation step → one module, with tests and worked examples.
  • Built unattended, once, after the plan is accepted.
  • Every run passes the gate first.

Principle 2 · Before model-written code is ever run

The code is read first: a calculation, nothing else

# calc/safety.py (ast walk, no model)
ALLOWED_IMPORTS = {decimal, datetime, math,
                   fractions, calendar, statistics}
FORBIDDEN_NAMES = {eval, exec, compile, open,
                   input, __import__, getattr,
                   setattr, globals, print, type …}
FORBIDDEN_ATTRIBUTES = {today, now, utcnow}
# also refused: any __dunder__ access,
# class, while, try, with, lambda, global

Why no clock?

A module that reads today() gives a different answer tomorrow. Today's date is passed in as an input instead.

Then a separate process

python -I runner.py <folder>: isolated mode, 30-second timeout, JSON in and out.

Honest limit

"A check on the code, not a sandbox: it refuses what it recognises."

Principle 2 · The only way a calculation runs

The gate: seven checks, in this order, on every single run

Is the module registered?"There is no registered module called…"
Are its files the ones that passed? (fingerprint)"…must be built again."
Is its plan step unchanged and built?STALE / NOT_BUILT
Did the caller give assumptions and an expected result?"…say what you expect the result to be."
Do the inputs fit the spec's types?BAD_INPUTS, with the problems
Do its tests pass right now?tests re-run every time, recorded in test_runs
Run it → row in calc_runsinputs, assumptions, expected, output, fingerprint, test_run_id

Every refusal is an event (calc.refused) and goes back to the model as the tool's error, so it adapts instead of improvising a number.

Principle 2 · Step 1 of the wedding plan

What a built step actually is: four small files

# modules/wedding_total_cost/module.py
from decimal import Decimal, ROUND_HALF_UP

def calculate(guest_count, dinner_cost_per_guest,
              extra_costs):
    if guest_count < 0:
        raise ValueError("Guest count cannot be negative.")
    ...
    total = Decimal(guest_count) * dinner_cost_per_guest
    for item in extra_costs:
        total += Decimal(str(item["amount"]))
    return total.quantize(Decimal("0.01"),
                          rounding=ROUND_HALF_UP)
# golden.json (one of four)

Principle 3 · Evidence · layer 3

Every number can be followed back.

Not all information is equal. Keep the trail: where each thing came from, and how far to trust it.

Without it

  • Everything treated as fact.
  • A rough guess used as the truth.
  • "I ran the numbers." No receipts.

With it

  • A number with no source is never shown.
  • Each figure links to its run, step and test run.
  • Chips under the reply show inputs, assumptions, results.

Principle 3 · A tripwire for made-up numbers

The number check reads every number before you do

A number may come only from

rundatainputnotebriefpersontoday
  • Reads numbers (43,000, $1.5k, 12%) and ISO dates, part by part.
  • Match within half the written precision: 1.9k backs anything 1,850–1,950.
  • 12% also matches 0.12.
  • Bare whole numbers 0–12 are skipped ("three payments").

1st unbacked reply

Sent back to the model, unseen: "[harness] Your reply was not shown. These numbers did not come from… Do not work numbers out yourself: run a module, or leave the number out."

2nd unbacked reply

Withheld. You see: "(The answer was held back, because it held numbers that no tested module produced: …)"

Also on tool inputs

run_module, save_input, ask_decision, the side assistant and the reviewer all pass through it.

Principle 4 · Accountability · layer 4

Ask only where a person must decide.

Agents face no real-world consequences. You do. Few gates, high signal.

Without it

  • "The stochastic machine said it was fine."
  • Approving every calculation.
  • Reviewing everything, so reviewing nothing well.

With it

  • Judgement calls stop and ask.
  • Assumptions run, but are marked.
  • Your figures change only with your yes.

Principle 5 · Verification · layer 5

A reviewer challenges the plan.

Experts don't check every cell. They know where it usually goes wrong, and roughly what the answer should look like.

Without it

  • Checking everything, line by line.
  • Or checking nothing.
  • No sense of what "about right" looks like.

With it

  • "Is the guest count really settled?"
  • "Is the price per guest all in?"
  • Each challenge is yours to use or dismiss.

Principle 5 · A separate look, on its own lane

The reviewer sees the thinking, not the conversation

Given

  • The plan: goal, steps, formulas, origins, open questions
  • Built specs and their departures
  • Assumptions and their status · decisions · saved inputs
  • Last runs' inputs and outputs
  • Earlier challenges and your replies to them

Never given

  • The analyst's conversation or the main chat
  • Any module's code
  • Lookups with a digit in them (refused: nothing personal leaves)

Principle 5 · Few challenges, worth reading

A challenge is kept only if it passes the same kind of checks

Kept only when

  • It names a real plan step; title 1–45 characters
  • A question proposes nothing; a challenge proposes something
  • Every source URL came from a lookup in this pass
  • Its numbers pass the number check
  • It doesn't repeat an open, used or dismissed one

Rank and cap

Sort by impact (high first), then the reviewer's order. Keep at most min(3, 5 − open): never more than five open.

Use this

Trunk node challenge_used (who: reviewer); your "use this" message goes to the analyst, and what it changes records its own node.

Dismiss

The branch dies, dimmed. The plan stays as it was.

Takeaways

Five moves you can copy into any agent harness

Tag every fact with its origin, and verify the tag in code

A quote must be in the user's words; a source must come from a real lookup.

Let the model write tools once; never let it compute

Separate writers from checkers by what they can see. Run every call through a gate that re-tests.

Put a tripwire on output

Any number without a source is sent back, then withheld. Build receipts from your own records, not the model's prose.

Grade interruptions: never, mark, stop

Models propose changes; only the person's yes applies them.

Add a reviewer with a different view, and a filter on it

Cap, rank and source-check its challenges so they stay worth reading.
